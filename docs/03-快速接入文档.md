# PCM-KMS 快速接入文档

版本：v1.1  
日期：2026-06-10

## 1. 文档目标

这份文档面向第一次接触 PCM-KMS 的开发者，目标是：

- 10 到 30 分钟内把系统跑起来
- 30 到 60 分钟内完成一个业务服务的接入验证

## 2. 推荐首次体验路径

第一次体验强烈建议走最小模式：

- SQLite
- 本地缓存
- 单体服务

原因很简单：

- 不需要先装 MySQL
- 不需要先装 Redis
- 不需要先处理复杂环境问题

## 3. 环境要求

### 后端

- JDK 8 或 11
- Maven 3.8+

### 前端

- Node.js 18+
- npm 9+ 或 pnpm 8+

## 4. 本地启动

### 4.1 配置主密钥

建议通过环境变量注入：

```bash
PCM_KMS_MASTER_KEY=please-change-this-master-key
```

### 4.2 启动后端

最小模式推荐配置：

```properties
kms.datasource.mode=sqlite
kms.cache.type=local
kms.security.strict-sign=false
```

启动命令：

```bash
mvn clean spring-boot:run -pl pcm-kms-server
```

### 4.3 启动前端

```bash
cd pcm-kms-admin-ui
npm install
npm run dev
```

## 5. 第一次使用流程

### 步骤 1：登录管理后台

本地模式可以提供初始化管理员，或在首次启动时自动生成。

### 步骤 2：创建租户

建议填写：

- `tenant_code`
- `tenant_name`

### 步骤 3：创建应用

建议填写：

- `client_name`
- `client_group`
- `contacts`
- `mobile`
- `job_no`
- `client_id`

说明：

- 创建应用后默认不直接生效
- 应用启用后再生成实际接入材料

### 步骤 4：启用应用

启用后建议自动生成：

- `client_id`
- `client_secret`
- `secret_id`
- 默认密钥别名
- 初始版本密钥材料

### 步骤 5：创建或补充业务密钥

建议填写：

- `alias`
- `algorithm`
- `cryptoType`
- `keyUsage`

### 步骤 6：绑定权限

至少配置：

- 哪个应用可以访问哪个别名
- 应用拥有 `encrypt`、`decrypt`、`sign`、`verify` 中哪些权限

## 6. API 调用规则

业务侧建议通过别名使用密钥，而不是通过 `secret_id`。

请求头建议：

```http
Content-Type: application/json
X-Client-Id: demo-client
X-Timestamp: 1718000000000
X-Nonce: 6f3c6ad2e5b14b95
X-Signature: xxxxxxxxxxxxx
```

推荐由 Starter 自动注入这些头，而不是手工拼装。

## 7. 加密接口示例

### 加密

```http
POST /api/open/crypto/encrypt
```

请求体：

```json
{
  "alias": "user-phone-aes",
  "plainText": "13800138000"
}
```

### 解密

```http
POST /api/open/crypto/decrypt
```

请求体：

```json
{
  "alias": "user-phone-aes",
  "cipherText": "Base64CipherText"
}
```

## 8. Starter 接入

### 8.1 引入依赖

```xml
<dependency>
    <groupId>com.pcm.kms</groupId>
    <artifactId>pcm-kms-client-starter</artifactId>
    <version>${pcm-kms.version}</version>
</dependency>
```

### 8.2 基础配置

```properties
kms.client.enabled=true
kms.client.server-url=http://localhost:8080
kms.client.client-id=demo-client
kms.client.client-secret=demo-secret
kms.client.sign-algorithm=HmacSHA256
```

### 8.3 编程式调用

```java
String cipherText = kmsClient.encrypt("user-phone-aes", "13800138000");
String plainText = kmsClient.decrypt("user-phone-aes", cipherText);
```

### 8.4 注解式增强

Starter 后续可支持：

- 字段注解方式
- 方法参数注解方式
- 方法返回值注解方式
- 集合、Map、嵌套字段路径处理

但原则不变：

- 编程式调用优先作为主路径
- 注解式能力作为可选增强

## 9. 常见问题

### 没有 Redis 能启动吗

可以。

配置本地缓存即可：

```properties
kms.cache.type=local
```

### 没有 MySQL 能启动吗

可以。

切换到 SQLite 模式即可。

### 为什么业务最好用 alias

因为：

- 语义更稳定
- 更适合版本管理
- 更适合权限控制
- 不需要业务直接感知内部 `secret_id`

## 10. 推荐验收动作

如果下面 6 步都能顺利完成，说明接入体验已经基本成立：

1. 启动后端
2. 启动前端
3. 创建应用并启用
4. 创建密钥并绑定权限
5. 用 Swagger 调一次加解密
6. 在 demo 服务中接入 Starter
