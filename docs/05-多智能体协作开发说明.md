# PCM-KMS 多智能体协作开发说明

版本：v1.0  
日期：2026-06-10

## 1. 目的

这份文档用于支持多个智能体或多个开发者在同一项目上并行工作、切换工作、保留上下文。

目标不是让每个参与者都重新理解全部设计，而是让任何新接手的人都能快速知道：

- 当前项目做到哪里
- 当前阶段的主目标是什么
- 自己应该改哪些部分
- 哪些设计不能随便改
- 完成后如何记录和交接

## 2. 项目当前主目标

所有协作者都必须优先围绕这三条目标工作：

- 一个能本地直接跑起来的 KMS
- 一个能被业务服务轻松接入的 KMS
- 一个你半年后再看也不会觉得太重的 KMS

如果某个方案违背这三条目标，即使技术上可行，也不应优先采用。

## 3. 协作总规则

### 3.1 先读哪些文档

任何智能体开始工作前，至少先读：

1. `README.md`
2. `docs/01-总体设计方案.md`
3. `docs/02-开发进度周期说明.md`
4. 与自己任务最相关的专项文档

### 3.2 哪些设计不能轻易推翻

- 单体优先的主路径
- SQLite 可运行
- Redis 可选
- 业务通过 alias 使用密钥
- Starter 以轻量接入为目标
- 自动签名和自动验签为默认体验

### 3.3 哪些地方可以逐步增强

- Gateway
- Nacos
- OpenFeign
- 指标监控
- Docker 化
- 注解式加解密能力

## 4. 推荐任务切分

### Agent A：后端骨架与基础设施

负责：

- Maven 模块结构
- Spring Boot 启动
- MySQL / SQLite
- Redis / 本地缓存
- Flyway

### Agent B：核心加解密与密钥管理

负责：

- 算法实现
- 密钥生成
- 密钥轮转
- 密钥管理接口

### Agent C：应用接入与 Starter

负责：

- client 注册和启用流程
- 签名与验签
- Starter
- 编程式 API
- 注解增强

### Agent D：前端管理台

负责：

- 登录
- 应用管理
- 密钥管理
- 审计日志查询

### Agent E：文档、测试与发布整理

负责：

- README
- 接入文档
- 测试样例
- handoff 记录整理

## 5. 工作前检查清单

开始任务前，必须明确：

- 当前属于哪个阶段
- 当前任务是否服务于三条主目标
- 当前改动是否会增加不必要复杂度
- 当前改动是否依赖未完成模块

如果答案不清楚，应先记录假设再动手。

## 6. 输出要求

每个协作者完成任务后，至少要留下：

- 改动范围
- 影响模块
- 是否改动了接口或配置
- 需要谁继续跟进
- 剩余风险

## 7. 交接规则

交接时统一写入：

- `docs/06-协作记录模板.md` 的实例记录

建议每次交接都包含：

- 日期
- 负责人
- 目标
- 已完成内容
- 未完成内容
- 下一步建议

## 8. 决策优先级

多个方案冲突时，按下面顺序判断：

1. 是否更容易本地运行
2. 是否更容易业务接入
3. 是否更容易长期维护
4. 是否更容易测试
5. 是否更容易扩展

如果一个方案只是“更先进”，但不满足前 3 条，不应优先采用。

## 9. 禁止事项

以下行为不建议在前期出现：

- 未经说明就引入大量新中间件
- 把单体主路径改成必须依赖分布式环境
- 让 Starter 强侵入业务系统
- 把文档和代码状态长期脱节
- 让配置只能在公司环境或特定机器下运行

## 10. 推荐协作节奏

推荐以“阶段 + 子任务 + 交接记录”的方式推进。

例子：

1. Agent A 完成后端骨架
2. Agent B 接着实现核心密钥能力
3. Agent C 基于稳定 API 做 Starter
4. Agent D 基于稳定 API 做前端
5. Agent E 在每阶段后同步文档和记录

这样切换成本最低，也最不容易互相覆盖。
