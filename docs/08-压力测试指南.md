# PCM-KMS 压力测试指南

版本：v1.0  
日期：2026-06-11

## 1. 测试目标

验证 PCM-KMS 在高并发、大数据量场景下的性能表现，核心指标：

- **TPS**：每秒事务处理数
- **平均延迟**：单次请求平均耗时（μs）
- **成功率**：请求成功占比
- **稳定性**：长时间运行是否出现内存泄漏、连接耗尽等问题

## 2. 测试环境建议

| 组件 | 配置 |
|------|------|

## 3. 快速开始

### 前置准备

1. 启动 KMS 服务端
2. 在管理后台创建应用并启用
3. 创建测试密钥（推荐 AES 算法，别名如 `stress-aes`）

### 运行压力测试

```bash
# 编译整个项目
cd pcm-kms
mvn clean package -DskipTests

# 运行压力测试
cd pcm-kms-stress-test
java -jar target/pcm-kms-stress-test.jar \
  --stress.enabled=true \
  --stress.alias=stress-aes \
  --stress.count=1000000 \
  --stress.threads=10
```

### 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--stress.enabled` | false | 是否启用压力测试 |
| `--stress.alias` | stress-aes | 密钥别名 |
| `--stress.count` | 1000000 | 测试请求数 |
| `--stress.threads` | 10 | 并发线程数 |
| `--stress.algorithm` | AES | 加密算法 |

## 4. 测试场景

### 场景一：百万次加密性能测试

模拟业务系统高频加密场景（如手机号、身份证号加密存储）。

测试流程：
1. 启动 N 个并发线程
2. 每个线程执行加密操作，生成随机明文
3. 统计 TPS、平均延迟、成功率

### 场景二：百万次加解密闭环测试

模拟真实业务中「加密存入 → 读取解密」的完整链路。

测试流程：
1. 预生成一批密文（10 万条）
2. 并发随机选取密文执行解密
3. 统计 TPS、平均延迟、成功率

### 场景三：百万次摘要性能测试

测试 SM3 摘要算法的吞吐量。

测试流程：
1. 并发执行 SM3 摘要计算
2. 统计 TPS、平均延迟

## 5. 结果解读

### 性能基准参考

以下为参考值（实际取决于硬件和网络环境）：

| 场景 | TPS 参考值 | 平均延迟参考值 |
|------|-----------|---------------|
| AES 加密（SQLite，10 并发） | 500-2000 | 500-2000 μs |
| AES 加密（MySQL+Redis，50 并发） | 2000-8000 | 100-500 μs |
| SM3 摘要（SQLite，10 并发） | 800-3000 | 300-1200 μs |

### 异常处理

| 现象 | 可能原因 | 建议 |
|------|---------|------|
| 成功率 < 99% | 服务端限流 / 连接池耗尽 | 调大 `kms.ratelimit.max-per-minute` |
| TPS 随时间持续下降 | 内存泄漏 / GC 压力 | 检查 JVM 堆内存配置 |
| 大量连接超时 | 线程数过多 / 网络瓶颈 | 降低并发线程数 |
| 签名验证失败 | 请求过期 / nonce 冲突 | 增大 `request-expire-seconds` |

## 6. 自定义测试

```java
@Component
public class CustomStressTest implements CommandLineRunner {
    @Autowired
    private KmsClient kmsClient;

    @Override
    public void run(String... args) {
        // 自定义测试逻辑
    }
}
```

- 异常日志（如有）
