## 1. 术语表

| 名词 | 解释 | 使用建议 |
|------|------|----------|
| **密钥别名（alias）** | 密钥和名称的映射，简化密钥ID的流转，KMS通过别名找密钥 | 配置 Starter 会默认创建一个别名 |
| **签名密钥（secret）** | 业务系统和KMS进行交互所必需的：1. KMS对业务系统进行身份识别，防伪造；2. 客户端自动对请求参数进行加签，防篡改 | 客户端服务配置项必填 |
| **密钥授权** | A服务授权给B服务，B服务拿到A服务的加密数据在有效期内可以直接解密。**这是单向授权**，若双方都互相可以解密，请配置2次 | 1. 共用数据库的情况；2. 存在敏感数据频繁交互的情况 |

## 2. 接入流程

```
申请入驻 → 获取签名密钥 → 引入 SDK → 配置参数 → 开始使用
```

### 2.1 租户入驻（接入时需要准备）

请填写下列表格，相关数据填写请参考下列说明：

| 字段名称 | 是否必填 | 说明 | 举例 |
|----------|----------|------|------|
| 应用ID（client_id） | 是 | 填写服务的 `spring.application.name`，每个环境可能不一致 | `iam-iamEhrService` |
| 应用分组（client_group） | 是 | 同服务发布的项目名称，比如 iam、base | `iam` |
| 应用名称（client_name） | 是 | 应用名称 | `考勤管理系统-服务端` |
| 应用授权列表 | 否 | 需要跨服务解密的授权关系。**单向授权**，双方互解需配2次。有效期默认1年 | `iam-iamEhrAdmin` → `iam-iamEhrApi` |
| 联系人邮箱 | 是 | 应用配置成功后会发送一份有签名密钥的邮件 | `xxxxx@bthome.com` |

> **注意**：每个环境（dev/test/uat/prod）各自独立，都需要进行接入。

### 2.2 页面操作步骤

```
应用列表 → 新增应用 → 启用应用 → 查看签名密钥
```

## 3. 详细步骤

### 3.1 引入 Maven 依赖

引入该 Starter 之后，在项目启动时会自动为该项目创建一个默认别名，后续使用注解的方法默认使用该别名。若想自定义一个新别名使用，可参考接口文档。

```xml
<dependency>
    <groupId>com.pcm</groupId>
    <artifactId>pcm-kms-client-starter</artifactId>
    <version>2.0.0</version>
</dependency>
```

### 3.2 配置文件

```yaml
# application.yml
kms:
  client:
    # KMS 服务地址
    server-url: http://kms-server:8080
    # 应用ID（入驻时获得）
    client-id: ${KMS_CLIENT_ID}
    # 签名密钥（入驻时获得，不同应用有各自密钥，不同应用无法复用）
    client-secret: ${KMS_CLIENT_SECRET}
    # 连接超时（毫秒）
    connect-timeout: 5000
    # 读取超时（毫秒）
    read-timeout: 10000
```

### 3.3 环境变量注入（生产推荐）

```bash
export KMS_CLIENT_ID=iam-iamEhrService
export KMS_CLIENT_SECRET=your_secret_here
```

## 4. 注解使用（Spring Boot Starter）

### 4.1 Mapper 层实现（DO 字段加解密）

#### 4.1.1 说明

该方式实现轻便简单，只需要在 DO 实体对应的字段上面添加如下注解就可以实现数据的加解密。该注解支持传统的 MyBatis XML 写法以及 MyBatis-Plus 写法。

- `@KmsEncryptField`：该字段在新增/修改时会进行加密，落库是密文。
  - `alias`：加密的别名（仅加密时有效），用于区分业务不同场景的加解密，不填写会使用默认别名。
- `@KmsDecryptField`：该字段在查询返回结果进行解密，该字段返回明文。

#### 4.1.2 示例代码

**DO 层需要加解密的字段添加如下注解：**

```java
@Data
@TableName("user_info")
public class UserInfoDO implements Serializable {
    private static final long serialVersionUID = -28999718139588302L;

    private Long id;

    @KmsDecryptField
    @KmsEncryptField
    private String encryptedName;
}
```

**XML 新增/更新/查询：**

```xml
<insert id="insert" keyProperty="id" useGeneratedKeys="true">
    insert into user_info(encrypted_name)
    values (#{encryptedName})
</insert>

<update id="update">
    update user_info
    <set>
        <if test="encryptedName != null and encryptedName != ''">
            encrypted_name = #{encryptedName},
        </if>
    </set>
    where id = #{id}
</update>

<select id="queryAll" resultMap="UserInfoMap">
    select id, encrypted_name
    from user_info
    <where>
        <if test="id != null">
            and id = #{id}
        </if>
        <if test="encryptedName != null and encryptedName != ''">
            and encrypted_name = #{encryptedName}
        </if>
    </where>
</select>
```

**MyBatis-Plus 新增/更新/查询：**

> 注：非示例的写法可能存在不支持的情况，若不支持可使用编程式调用进行手动转换。

```java
// 新增
userInfoManager.save(userInfoDO);

// 更新 示例1
userInfoManager.updateById(userInfoDO);

// 更新 示例2
LambdaUpdateWrapper<UserInfoDO> lambdaUpdateWrapper = new LambdaUpdateWrapper<>();
lambdaUpdateWrapper.eq(UserInfoDO::getId, 1);
userInfoManager.update(userInfoDO, lambdaUpdateWrapper);

// 查询
userInfoManager.lambdaQuery().list();
```

### 4.2 自定义注解实现（方法级加解密）

#### 4.2.1 说明

该方法使用轻便简单，只需要在调用的方法层添加注解实现即可，无需对原对象数据进行侵入式的改造。需要注意的是该方法需要被 Spring 管理。

- `@KmsMethod`：启用方法加解密注解。
  - `enableParams`：是否加解密入参（默认开启 true）
  - `enableResult`：是否加解密结果（默认关闭 false）
  - `fields`：enableResult 为 true 时生效，需要加/解密的字段路径（支持嵌套）。使用 `$` 表示整个元素
  - `alias`：加密的别名，不填写使用默认别名
  - `encrypt`：true 加密，false 解密。默认 true
- `@KmsParam`：入参注解，添加到方法入参可对方法进行加解密。
  - `fields`：需要加/解密的字段路径（支持嵌套）。使用 `$` 表示整个元素
  - `alias`：加密的别名，不填写使用默认别名
  - `encrypt`：true 加密，false 解密。默认 true

#### 4.2.2 方法入参对象加密/解密

```java
@KmsMethod
@Override
public UserInfoVO t1(
        @KmsParam(fields = {"encryptedName", "encryptedName2"})
        UserInfoVO userInfoVO) {
    log.info("t1:{}", JSONObject.toJSONString(userInfoVO));
    return userInfoVO;
}

@KmsMethod
@Override
public UserInfoVO t2(
        @KmsParam(fields = {"encryptedName", "encryptedName2"}, encrypt = false)
        UserInfoVO userInfoVO) {
    log.info("t2:{}", JSONObject.toJSONString(userInfoVO));
    return userInfoVO;
}
```

## 5. 编程式调用

### 5.1 方法加解密

```java
@Resource
private KmsClient kmsClient;

// 单条加密
public String encrypt(String plainText) {
    return kmsClient.encrypt(plainText, "default-alias").getCipherText();
}

// 单条解密
public String decrypt(String cipherText) {
    return kmsClient.decrypt(cipherText, "default-alias");
}

// 批量加密（底层实现做了分批处理）
public Map<String, String> encryptBatch(List<String> plainTexts) {
    return kmsClient.encryptBatch(plainTexts, "default-alias");
}

// 批量解密（底层实现做了分批处理）
public Map<String, String> decryptBatch(List<String> cipherTexts) {
    return kmsClient.decryptBatch(cipherTexts, "default-alias");
}
```

### 5.2 直接调用 REST API（非 Spring Boot 项目）

#### 签名算法

```
sign = HMAC-SHA256(clientSecret, body + timestamp + nonce)
```

#### Java (OkHttp) 示例

```java
public class KmsHttpClient {
    private final String serverUrl;
    private final String clientId;
    private final String clientSecret;
    private final OkHttpClient httpClient = new OkHttpClient();

    public String encrypt(String plainText, String alias) throws Exception {
        String body = String.format(
            "{\"plainText\":\"%s\",\"alias\":\"%s\"}", plainText, alias);
        String timestamp = String.valueOf(System.currentTimeMillis());
        String nonce = UUID.randomUUID().toString().replace("-", "");
        String sign = hmacSha256(clientSecret, body + timestamp + nonce);

        Request request = new Request.Builder()
            .url(serverUrl + "/api/crypto/encrypt")
            .post(RequestBody.create(body,
                MediaType.parse("application/json")))
            .header("X-Client-Id", clientId)
            .header("X-Timestamp", timestamp)
            .header("X-Nonce", nonce)
            .header("X-Sign", sign)
            .build();

        try (Response response = httpClient.newCall(request).execute()) {
            return response.body().string();
        }
    }

    private String hmacSha256(String key, String data) throws Exception {
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(
            key.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        byte[] result = mac.doFinal(data.getBytes(StandardCharsets.UTF_8));
        return HexFormat.of().formatHex(result);
    }
}
```

#### Python 示例

```python
import requests
import hmac
import hashlib
import time
import uuid
import json

class KmsClient:
    def __init__(self, server_url, client_id, client_secret):
        self.server_url = server_url
        self.client_id = client_id
        self.client_secret = client_secret

    def _sign(self, body, timestamp, nonce):
        data = body + timestamp + nonce
        return hmac.new(
            self.client_secret.encode(),
            data.encode(),
            hashlib.sha256
        ).hexdigest()

    def encrypt(self, plain_text, alias):
        body = json.dumps({"plainText": plain_text, "alias": alias})
        timestamp = str(int(time.time() * 1000))
        nonce = uuid.uuid4().hex
        sign = self._sign(body, timestamp, nonce)

        resp = requests.post(
            f"{self.server_url}/api/crypto/encrypt",
            data=body,
            headers={
                "Content-Type": "application/json",
                "X-Client-Id": self.client_id,
                "X-Timestamp": timestamp,
                "X-Nonce": nonce,
                "X-Sign": sign,
            }
        )
        return resp.json()

    def decrypt(self, cipher_text, alias):
        body = json.dumps({"cipherText": cipher_text, "alias": alias})
        timestamp = str(int(time.time() * 1000))
        nonce = uuid.uuid4().hex
        sign = self._sign(body, timestamp, nonce)

        resp = requests.post(
            f"{self.server_url}/api/crypto/decrypt",
            data=body,
            headers={
                "Content-Type": "application/json",
                "X-Client-Id": self.client_id,
                "X-Timestamp": timestamp,
                "X-Nonce": nonce,
                "X-Sign": sign,
            }
        )
        return resp.json()
```

## 6. 前后端加解密流程

### 6.1 前端加密 → 后端解密

```
前端                          后端                        KMS
 │                             │                          │
 │  1. 用户输入敏感数据          │                          │
 │  2. 调用后端获取公钥接口       │                          │
 │  ──── GET /api/crypto/     │                          │
 │       public-key/{alias} ──→│                          │
 │                             │  3. 查询公钥              │
 │  ←──── 返回公钥 ────────────│                          │
 │                             │                          │
 │  4. 前端使用公钥加密数据      │                          │
 │  5. 提交加密后的数据          │                          │
 │  ──── POST /api/xxx ──────→│                          │
 │                             │  6. 需要解密时调用 KMS    │
 │                             │  ──── POST /api/crypto/  │
 │                             │       decrypt ──────────→│
 │                             │  ←──── 返回明文 ─────────│
 │                             │                          │
 │  ←──── 返回结果 ────────────│                          │
```

### 6.2 后端加密存储 → 后端解密展示

```
业务服务                       KMS                         数据库
 │                             │                            │
 │  1. 接收明文数据              │                            │
 │  2. 调用 KMS 加密            │                            │
 │  ──── POST /api/crypto/    │                            │
 │       encrypt ────────────→│                            │
 │  ←──── 返回密文+版本 ───────│                            │
 │                             │                            │
 │  3. 密文存入数据库 ──────────────────────────────────→   │
 │                             │                            │
 │  4. 查询时取出密文 ←──────────────────────────────────   │
 │                             │                            │
 │  5. 调用 KMS 解密            │                            │
 │  ──── POST /api/crypto/    │                            │
 │       decrypt ────────────→│                            │
 │  ←──── 返回明文 ───────────│                            │
 │                             │                            │
 │  6. 返回明文给前端            │                            │
```

## 7. 常见问题

### Q1：Sign validation failed（签名验证失败）

**解决办法**：
1. 检查签名密钥是否正确配置，和应用ID对应的服务一致
2. 检查应用ID是否和入驻时填写的一致
3. 检查时间戳是否在有效期内（默认 5 分钟窗口）
4. 检查 nonce 是否重复使用

### Q2：加密后的密文长度是多少？

| 算法 | 明文 16 字节 | 明文 256 字节 |
|------|-------------|--------------|
| AES-128-CBC | ~64 字符 (Hex) | ~544 字符 (Hex) |
| SM4-CBC | ~64 字符 (Hex) | ~544 字符 (Hex) |
| RSA-2048 | ~684 字符 (Base64) | ~684 字符 (Base64) |

### Q3：没有 Redis 能跑吗？

能。V2.0 默认使用 Caffeine 本地缓存，单机部署完全够用。多机部署时建议配置 Redis。

### Q4：密钥轮转后旧数据还能解密吗？

能。解密时会根据密文中携带的版本号自动匹配对应版本的密钥材料。旧版本密钥不会被删除，只是不再用于新加密。

### Q5：支持哪些加密算法？

| 类型 | 算法 | 说明 |
|------|------|------|
| 对称加密 | AES-128-CBC | 最常用，速度快 |
| 对称加密 | SM4-CBC | 国密标准 |
| 非对称加密 | RSA-2048 | 公钥加密，私钥解密 |
| 非对称加密 | SM2 | 国密非对称 |
| 签名 | SHA256withRSA | 数字签名 |
| 摘要 | MD5 / SHA256 / SM3 | 哈希摘要 |

### Q6：如何从旧版 KMS（Dubbo）迁移到新版（HTTP REST）？

1. 在新版 KMS 中创建对应的应用和密钥
2. 替换 Maven 依赖：`kms-encrypt-starter` → `pcm-kms-client-starter`
3. 修改配置：`kms.consumer.private.key` → `kms.client.client-secret`
4. 注解保持不变（`@KmsEncryptField`、`@KmsDecryptField`、`@KmsMethod`、`@KmsParam`）
5. 编程式调用：`KmsDubboCryptoService` → `KmsClient`
6. 逐应用灰度切换，验证加解密结果一致

### Q7：每个环境都需要单独接入吗？

是的。dev/test/uat/prod 每个环境各自独立，都需要进行接入。应用ID 每个环境可能不一致，请分别确认。
